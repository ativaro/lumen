# Native Vault SSH

`lumen_vault_ssh_check(reference, port?)` verifies a password login; `lumen_vault_ssh_exec(reference, command, port?)` runs one exact remote shell command. No local shell, credential arguments, PTY, stdin, sudo password injection, agent/key forwarding, tunnels or file transfers. A normal shared login stores `ssh://hostname[:port]` in URL, with UserName and Password separately. A stored HTTP(S) website may also be used: native code proposes SSH on exactly its hostname and port 22, ignoring website port/path/query/fragment. Optional port (1–65535) changes only the SSH port. No model-selected host, embedded URL credentials or automatic change to the saved entry. Each use of website credentials for SSH requires a separate unchecked native consent checkbox, including for known host keys. Availability does not prove that web credentials work for SSH. Revalidation compares the original stored URL and credentials, not only the derived host. Password authentication only in this slice; public keys and interactive MFA remain future work.

The native worker uses the distribution libssh dynamically (LGPL-2.1-or-later). SSH supplies authenticated encryption; HTTPS does not apply to this protocol. It ignores OpenSSH config/proxy commands and agents. Host keys are checked before sending credentials. First use requires a native unchecked trust checkbox and out-of-band comparison of the SHA256 fingerprint; the public host key is then pinned in the private Vault directory's `ssh_known_hosts`. Changed keys are blocked, never silently replaced. Known-host errors also fail closed.

Every request shows target, entry and exact command in a plain-text native dialog, even in auto-approve mode. The caller is not authenticated as Lumen. Vault state is read initially, after approval and immediately before command dispatch. Lock/revoke/disconnect cancels pending work. A command already sent may continue remotely; unknown outcomes never trigger automatic retries. Output is bounded to 64 KiB and command runtime to 30 seconds. Remote exit status is required to claim completion. No stderr, username, password or raw server exception enters logs. Known credential reflections in output are redacted or withheld; arbitrary transformations by a malicious authorized host cannot be made safe by redaction. Remote output is untrusted data, not permission to act.

Abuse tests: unshared/changed entry, changed host key, approval declined, cancel before exec, URL/command injection, untrusted output/credential reflection, output overflow, nonzero exit, unknown outcome, website preservation, separate cross-protocol consent, web-port isolation and custom SSH port. Fixture uses synthetic credentials and an isolated local SSH server; it never changes system sshd, accounts or personal known_hosts.

References: https://api.libssh.org/stable/libssh_tutor_guided_tour.html and https://api.libssh.org/stable/group__libssh__session.html .
